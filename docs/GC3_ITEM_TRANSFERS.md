# GC-3: authoritative ordinary item transfers

Baseline: `0e380cc27e6c20516fe0f3f4c81b895310124f62`, clean branch
`feat/sm-gc3-item-transfers`. GC2 `5ff7a80`, RF4 `4e4e678` and position repair
`7da1137` are ancestors of the fetched main. No applicable AGENTS.md exists.
Engine/SRD remain 0.6.0 at `675552406e67470bf3456fe90e88c4f1595bf324`.

## Frozen minimal responsibility table (before implementation)

| Fact | Authority / writer | Consumers and projection |
|---|---|---|
| Object identity and ordinary world location | WorldFacts, `objects` | Existing scene, spatial and event readers |
| Portable instance identity, type, unit balance and exclusive location | WorldFacts, additive Schema 24 object fields | Scene/Cell **or** actual carrier; carried coordinates derive from CharacterFacts |
| Existing RF4 owned InventoryEntry facts | CharacterFacts, `mechanical_components.inventory_json` | Complete validation before Snapshot owner filtering |
| GC3 owned InventoryEntry subset | Generated by CharacterFacts from WorldFacts portable facts in the same executor transaction | Same instance ID; ground items have no RE owner entry |
| `characters.inventory_json` | CharacterFacts; existing values retained, affected slug membership generated from full owned inventory | Compatibility `carried_item_slugs`; type identity never instance identity |
| Equipment fields | Existing CharacterFacts mechanical metadata | Pickup never equips; ambiguous slug equipment prevents drop |
| Commands, version, RNG and receipt | Existing CommandRuntime / SessionAccess | Existing outer transaction and reliable NPC handoff |
| Physical action evidence, events and Outbox | Existing EventCapture / EventPersistence | Pickup captures before removal; drop captures after placement |

One WorldHandler transfer executor coordinates the two existing fact owners.
Handlers cannot separately edit portable inventory projections. WorldFacts rejects
legacy placement/switch writes for portable instances. CharacterFacts validates the
portable subset against its source before reads or regeneration; it preserves all
unrelated RF4 entries, quantities, charge balances, resources, casting and effects.
There is no third independently writable backpack.

Package /4 explicitly grants ordinary public portable capabilities. Earlier
Packages and existing saves acquire none. New portable units have quantity 1;
legacy instances/stacks are preserved, without inventing a world identity for them.
Full current noncombat /17 foundations are required for /4. Authored initial
carriers use a reviewed actor/template reference and must match explicit initial
InventoryEntry facts. Fresh creation applies configuration once; resume never does.

This batch excludes combat transfers, contested/hidden property, containers,
stealing, locks, breakage, equipment changes, use/consumption, stack operations,
encumbrance rules, automatic pickup, automatic time and free-text plans.

## Implemented local contract

All writes use the existing `submit_command(TypedCommand, package, context=...)`.
Envelope Actor identity is supplied by the authenticated adapter, never by the
model's assertion of ownership. Both payloads use `item-transfer/1`:

| Command | Payload | Admission |
|---|---|---|
| `world.pickup_item` | `PickupItem(instance_id, scene_id, expected_cell)` | Existing approved ground unit in the actual Actor's local visible/reachable scope |
| `world.drop_item` | `DropItem(instance_id, scene_id, to_cell)` | That Actor currently carries the unit; target is an approved local ground cell |

Extra fields, foreign Actors, arbitrary operations and noncanonical cells cannot
grant a capability. All lookups include Session identity. Reusing a command key
with different parameters conflicts. OCC and current control are checked inside
the existing serialized write transaction. Domain refusals retain their ordinary
receipt; storage faults roll back the entire transaction and leave no receipt.
No ordinary transfer advances RNG or game time.

`read_carried_items(session_id, actor_id, package, *, context)` returns a detached
`CarriedItemsView(actor_id, world_version, entries)` with typed RE InventoryEntry
values. Trusted owners may read their PC/currently granted NPC; NPCContext may
read only its own currently authorized actor. It is not a world item catalogue.
Missing mechanical inventory fails closed. `query_world_action` uses the same
admission and performs no writes. Unknown and unseen target references receive
the same generic target refusal, including through legacy PlaceObject queries.

Package `state-machine-foundation/4` retains /3 navigation configuration and adds
the required closed `item_transfers` list (maximum 128):

```json
{
  "instance_id": "object.dagger_a",
  "item_slug": "dagger",
  "initial_owner_id": null,
  "quantity": 1,
  "charges_remaining_per_unit": 0,
  "policy": "ordinary_public"
}
```

Each ID references one existing authored object. Its Scene must have approved
public interactions and a fine Grid; the object has no switch, movable or blocking
capability. Ground configuration uses that object's validated initial Scene/Cell.
An explicit initial carrier uses an actual authored NPC or selected PC template;
its initial typed inventory must already contain precisely the matching instance.
Fresh initialization remaps the selected PC to the actual Session Actor. Actual
item slugs are checked against the fixed loader while creating the Session.
There is no name-based item behavior or synthetic mechanical asset.

Schema 24 rebuilds only the current `objects` table, preserving all original
columns/rows and adding nullable `carrier_id` / `item_json`. SQL CHECK and composite
foreign keys enforce a single location and a real same-Session carrier. Portable
unit metadata remains on that original object during both location modes. The
portable RE inventory subset is generated from it and checked on full-component
reads before filtering to Snapshot actors. Unrelated legacy InventoryEntry facts
remain authoritative in the existing RF4 component. Only the inventory column is
updated by transfer; resources, casting and effects are never replaced.

`instance_id` equals the original object ID, not item_slug. Moving the carrier
does not rewrite the object's row. An owned entry has the actual Actor owner,
the unchanged slug/quantity/per-unit charge balance, and trusted `accessible=True`
for this ordinary public profile. Accessibility describes the approved mechanical
projection; it is not an authorization grant. Legacy inaccessible entries and
larger quantities are retained verbatim. Dropping one instance removes the type's
slug only when no remaining positive-quantity owned instance of that type exists.

## Boundaries and consumer audit

| Surface | GC3 behavior |
|---|---|
| Scene snapshot, SpatialView, occupants, obstruction and consistency | Ground uses current Scene/Cell; carried has neither and is excluded automatically |
| Scene revisit / resume | Existing scene rows are retained; initial configuration is never replayed |
| Legacy PlaceObject / switches / automatic effects | Portable mutations are refused by the fact owner; query authorization precedes capability diagnostics |
| Navigation | Ordinary busy checks remain; no implicit pickup, no current_activity override and no dynamic replanning change |
| Equipment | Pickup changes no grip, held weapon, armor, shield, AC, proficiency or budget |
| Drop safety | Refuse a matching held weapon slug, ambiguous occupied other hand, equipped shield, potentially worn armor or casting-material instance binding |
| Actor state | Existing death/HP/condition/concentration/activity guards plus explicit mechanical owner and effect validation |
| Space | Existing RE GridTopology visibility and legal adjacent reach; walls, closed thresholds and occupied targets remain barriers |
| Small ground items | No new movement blocking, cover, physics or standing-cell occupancy semantics |
| RulesAdapter | Existing current character/component reads supply CombatSnapshot, NonCombatSnapshot, availability, evaluation and combat initialization |
| NPC Result | NPCPickupIntent / NPCDropIntent become reliable pending handoffs; Task supplies identity and command association, dispatch rechecks control |
| EventCapture | Pickup freezes before removal; drop freezes after placement. Payload records actual Actor/cell; object origin records actual item position |
| Carried object event sources | WorldFacts derives current Scene/Cell from the actual carrier, never initial Package or closed actor_zone |
| Historical perception | Evidence /4-/5 shapes and RF4 position repair remain; historical reads never recover positions from current item facts |

The single executor coordinates WorldFacts and CharacterFacts inside the existing
command savepoint and outer transaction. Item location, mechanical instance,
carried slug projection, phase evidence, semantic event, Outbox/queue, version and
receipt commit together. Capture/persistence failure cannot strand a half-transfer.
Two simultaneous actors can produce at most one successful pickup; that storage
property does not implement contested ownership adjudication.

## Reproduction and support matrix

```powershell
.venv/Scripts/python.exe examples/item_transfers.py
```

The [original Package](../examples/gc3_items.json) and
[public example](../examples/item_transfers.py) use a fresh real SQLite database,
the installed pinned assets and the common navigation pump. Authored decisions
choose destinations and then issue transfers; no LLM or Plan.steps interpretation
is claimed. The example picks up a canonical dagger and rope, carries both across
Scenes, drops the dagger and lets an authorized NPC acquire the same instance.

| Validation | Evidence |
|---|---|
| Two types, two same-type instances, PC and NPC | Common executor, same instance IDs, no ground ghost or duplicate owner |
| Movement, revisit and new-process resume | Public navigation; separate Python restore; all rows unchanged by reads |
| Real RE | Actual accepted generic check with captured request; supported rapier availability after combat initialization with current inventory |
| Equipment / balances | Same-slug weapon, other-hand, armor and shield refusals; quantity 7 / charges 2 / inaccessible legacy entry and portable charges 3 preserved |
| Authorization / busy / scope | Far, walls, dark, cross-Scene, ungranted/cross-Session Actor, active navigation, foreign Drop and legacy entry refusals |
| Faults / retries | Real SQL failures at object, component, character, evidence, Outbox and receipt writes; full-table comparisons and exact retry |
| Concurrency / OCC / lost response | Two SQLite connections and actors; same-key conflict; receipt reconciliation and idempotent replay |
| Reliable NPC outputs | Real Task and synthetic, explicitly typed Result for both pickup/drop; pending-only Meta, replay and revoked controller refusal |
| Compatibility | Genuine archived Schema23 runtime; atomic upgrade failure/retry and exact original columns, receipts and evidence preservation |

Old Package /1-/3 and legacy storage data retain their existing rules/admission
policy. They are not assigned fabricated instance identities or pickup grants.
Legacy owned inventory without a corresponding approved portable world instance
can still participate in its existing rules profile, but cannot be dropped by GC3.
Future containers, locks, equipment identity, stack operations, encumbrance, item
effects, combat transfers and contested ownership require separate reviewed work.
