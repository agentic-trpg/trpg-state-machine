## Existing improvements and legitimate consumers

Schema39 `InstanceData` has migrated current effective capability/Scene/NPC configuration reads. Package remains valid for fixed pin checks, initial and delayed creation of absent targets, explicit upgrade/source audit, static event programs, first mechanical creation and static navigation prediction; missing existing instance data fails rather than falling back. General dynamic spawn/dependency creation remains absent.

`ContainmentState` now builds adjacency once per operation/list, memoizes definition/weight reads, updates candidate adjacency and clears weights on relocation. The `(session_id,container_id,object_id)` index supports ordered direct children. These implemented improvements have `test_instance_containment.py`/`test_instance_config_migration.py` coverage and historical acceptance in [Instance Progress](../INSTANCE_CONFIGURATION_PROGRESS.md), but do not prove SQL locality or remove global inventory closure.

GridMaps uses transaction-visible content keys, immutable prepared input and bounded Store-local reuse; Environment has authoritative source/protection versions and bounded caches. Their actual progress is in [Grid](../GRID_SERVICE_PROGRESS.md) and [Environment](../ENVIRONMENT_SERVICE_PROGRESS.md). Retain rollback/old-reader/isolation/disclosure behavior when optimizing cold reads. Do not mistake time TTL or a lone world_version for complete cache validity.

Encounter Snapshot construction/validation must include its full mechanical dependency closure; initialization compatibility, explicit full-scene batch results, whole-map path planning and requested diagnostics are legal full consumers. A whole-session OCC ReadVersion is a conservative version fence, not evidence of a full scan. No performance work may weaken these requirements.
